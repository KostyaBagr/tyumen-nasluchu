# Защита проекта: «Тюмень на слуху»

Учебный многостраничный сайт (HTML + CSS, минимальный JS).  
Цель оценки: уверенная **4 / ближе к 4.5** - все обязательные требования + бургер, форма, CSS-переменные.

---

## 1. Краткий доклад (3-5 минут)

Можно читать почти дословно, лучше своими словами.

> Здравствуйте. Мой проект - городской блог **«Тюмень на слуху»**.  
> Это личный гид по Тюмени: куда сходить, где поесть по пути и как пройти центр пешком за один день.
>
> Сайт на **чистом HTML и CSS**, без фреймворков. JavaScript использован только для **бургер-меню** - около 20 строк, он не подменяет структуру страницы.
>
> **Пять страниц:**
> 1. **Главная** - герой-блок с названием блога и входом в разделы  
> 2. **Места** - достопримечательности карточками  
> 3. **Еда** - гастро-советы, **видео** с YouTube и **аудиоплеер**  
> 4. **Маршруты** - пеший день и **интерактивная Яндекс.Карта** набережной  
> 5. **О блоге** - текст об авторе и **форма обратной связи**
>
> Стили вынесены в один файл `css/style.css`: цвета, шрифты и отступы заданы через **CSS-переменные**, поэтому на всех страницах единый вид.
>
> На каждой странице есть **анимация** (keyframes или transition/transform).  
> Сайт **адаптивный**: от 320px, на мобильных меню сворачивается в бургер.
>
> Сложности: подобрать спокойную палитру «река + кирпич», вписать iframe видео и карты без поломки сетки, сделать меню удобным на узком экране.

**Если спросят «покажите»** - дальше сценарий из раздела 6.

## 3. Как закрыты критерии задания

| Требование | Где смотреть |
|------------|----------------|
| Единый стиль | `css/style.css` → блок `:root` (цвета, шрифты, отступы) |
| ≥5 страниц + меню | Все `*.html`, блок `<nav class="site-nav">` |
| Header / main / footer | На каждой странице семантические теги |
| Анимация на каждой странице | См. таблицу ниже |
| ≥3 изображения | `images/набережная-тюмень.jpg`, `мост-влюбленных.jpg`, `цветной-бульвар.jpg` и др. |
| Видео | `food.html` → `<iframe>` YouTube |
| Аудио | `food.html` → `<audio>` + `audio/marmixer-deep-sea-324392.mp3` |
| Карта | `routes.html` → iframe Яндекс.Карт, маркер у набережной |
| Адаптив + мобильное меню | `@media` в CSS + `js/menu.js` |

### Анимации по страницам

| Страница | Эффект |
|----------|--------|
| `index.html` | `@keyframes fadeUp` у hero; hover у кнопок |
| `places.html` | hover карточек: `transform: scale` + тень |
| `food.html` | `@keyframes pulse` у декора плеера; hover у `.media-block` |
| `routes.html` | `@keyframes markerPop` у номеров шагов маршрута |
| `about.html` | transition у полей формы; underline-анимация ссылок |

## 4. Технологии и решения (коротко)

- **Семантика:** `header`, `nav`, `main`, `section`, `article`, `footer`, `address`, `figure` (где уместно).
- **Сетки:** Flexbox (шапка, hero-кнопки) и CSS Grid (карточки, маршруты, about).
- **Переменные CSS:** чтобы не копировать цвета и радиусы по файлу.
- **Карта через iframe:** не нужен API-ключ, карта сразу интерактивна (zoom, drag). Рядом текстовый маршрут - чтобы было информативно.
- **JS только на меню:** по заданию структура не должна подменяться скриптом; контент весь в HTML.
- **Форма без бэкенда:** показывает умение верстать поля; на защите можно честно сказать, что отправка на сервер не входила в задачу.

## 5. Вопросы преподавателя и ответы

### Общие

**1. Почему выбрали тему Тюмени?**  
Интересный город с сильной набережной, удобно строить маршрут и карту вокруг одной локации - реки Туры.

**2. Почему не Bootstrap / React?**  
По заданию - чистый HTML/CSS, чтобы показать верстку и адаптив самостоятельно.

**3. Зачем одна таблица стилей?**  
Единый стиль на всех страницах, меньше дублирования, проще править палитру через `:root`.

**4. Что такое CSS-переменные?**  
Кастомные свойства в `:root` (`--color-river`, `--radius`…). Меняешь в одном месте - обновляется весь сайт.

**5. Чем `<section>` отличается от `<div>`?**  
`<section>` - смысловой блок с темой; `<div>` - просто контейнер без смысла. Семантика помогает структуре и доступности.

**6. Зачем `<article>`?**  
Для самостоятельной единицы контента (карточка места, тизер), которую можно воспринимать отдельно.

### Адаптив и меню

**7. Как сделано мобильное меню?**  
Кнопка `.nav-toggle` в JS вешает/снимает класс `nav-open` на `body`. В CSS при этом классе меню раскрывается (`max-height`), иконка превращается в крестик.

**8. Почему JS, а не только CSS?**  
Чекбокс-хак тоже возможен, но с кнопкой и `aria-expanded` проще для доступности. JS не строит HTML - только класс.

**9. Как проверяли адаптив?**  
DevTools → Device Toolbar: ширины около 320, 480, 768, 1280, 1920. Смотрел, чтобы не было горизонтального скролла.

**10. Что ломалось на мобильном?**  
Широкие iframe (видео/карта) - обернул в контейнеры с `aspect-ratio` / фиксированной высотой и `max-width: 100%`.

### Мультимедиа и карта

**11. Почему видео через YouTube, а не файл?**  
Меньше вес проекта, не нужно хранить большой mp4 в архиве, iframe стабильно работает.

**12. Где аудио?**  
Страница «Еда», блок «Саундтрек прогулки», тег `<audio controls>`, файл `audio/marmixer-deep-sea-324392.mp3`.

**13. Почему карта iframe, а не JS API?**  
Для учебного проекта iframe достаточно: интерактив есть, ключ API не нужен, проще защищать.

**14. Что показано на карте?**  
Район набережной Туры в Тюмени, координаты в параметрах `ll` и метка `pt`.

### Стиль и анимации

**15. Откуда палитра?**  
Холодный синий - река / небо, кирпичный акцент - историческая застройка. Не «фиолетовый градиент из шаблона».

**16. Какие шрифты?**  
Nunito Sans (текст и заголовки) с Google Fonts - ровный гротеск без «неровностей» серифа.

**17. Не мешают ли анимации?**  
Короткие, в основном на hover и при загрузке hero/маркеров. Нет бесконечной мигалки по всему экрану (pulse только у декора плеера).

**18. Что бы улучшили дальше?**  
Подключить отправку формы (Formspree и т.п.), заменить иллюстрации на свои фото, добавить тёмную тему или второй маршрут.

### «Сам ли делал?»

**19. Объясните бургер своими словами.**  
В HTML есть кнопка из трёх полосок. По клику скрипт добавляет класс на `body`. В CSS для этого класса меню становится «высоким» и видимым, полоски поворачиваются в крест.

**20. Где media queries?**  
В конце `css/style.css`: `1024px`, `768px`, `480px` - колонки сетки схлопываются, появляется бургер.

**21. Почему относительные пути?**  
Чтобы сайт открывался и с диска, и на GitHub Pages без правки ссылок.

## 6. Сценарий демонстрации (2-3 минуты)

1. **Главная** - название блога в hero, кнопки, единый header.  
2. **Сжать окно / телефон** - показать бургер, открыть «Места».  
3. **Места** - навести на карточку (подъём/scale).  
4. **Еда** - запустить видео (или показать iframe), включить аудио на пару секунд.  
5. **Маршруты** - подвигать карту, приблизить; показать анимацию номеров шагов (обновить страницу).  
6. **О блоге** - кликнуть в поле формы (подсветка focus), показать underline у ссылки.
